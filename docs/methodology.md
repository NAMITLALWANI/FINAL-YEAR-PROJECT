# System methodology

## Data flow

1. Connectors fetch source records; normalization standardizes available publication fields.
2. The existing publication deduplicator groups records using identifiers, title, authors, and year signals. Its behavior is unchanged by the retrieval work.
3. The relational database retains source records, canonical publications, source lists, and deduplication provenance.
4. An explicit index build resolves duplicate-group external record IDs back to source records, constructs one document per canonical publication, and hashes the normalized representation plus index/model versions.
5. Chroma upserts changed documents, preserves unchanged embeddings, removes stale projected entries, and checks collection row count. `/health` reports whether the configured retrieval collection is absent, empty, ready, or unavailable without loading the embedding model. `/health` reports whether the configured retrieval collection is absent, empty, ready, or unavailable without loading the embedding model.
6. Query-time retrieval uses Chroma cosine similarity and optional exact DOI, year, or primary-source filters. The displayed score is a retrieval ranking signal, not a probability.
7. Author Resolution V1 independently creates candidate hypotheses, scores structured evidence, and chooses automatic/manual/unresolved status. Retrieved papers are contextual evidence in the candidate review UI; they do not change V1 candidate scores or statuses.
8. If a provider is configured, an LLM may write claims citing retrieved records. Claims without supplied document IDs are dropped, and the model's uncited summary is not displayed. If no claims survive citation-ID validation, the API reports a validation fallback. Matching a valid document ID does not prove that a claim is semantically supported; human review remains necessary. No-hit/provider-failure cases abstain or use deterministic fallback text.
9. A failed candidate-source request returns an availability error and must not be persisted as an unresolved identity. A successful empty candidate result may be recorded as unresolved, and a reviewer may explicitly mark a query unresolved.

## Index document and versioning

The document body includes existing title, abstract, author list in stored order, venue, year, and extracted source-record topic/concept and publication affiliation mentions. Affiliation mentions are not linked to a particular author. Metadata contains a stable ID derived from canonical ID; relational publication ID; provider list; local source-record IDs and provider IDs; DOI; URL; abstract source; source ingestion time; content hash; index version; and embedding model. Missing values stay absent/empty and are not synthesized. The current schema is `scholarly-record-v1`, collection `scholarly_records_v1`, model `all-MiniLM-L6-v2`, cosine space, max top-k 20, default top-k 5.

## Evaluation methodology

Application tests verify stable document construction, absent-abstract handling, provenance retention, deterministic explanation fallback, citation-ID filtering, duplicate source-profile reuse, and end-to-end API safeguards on disposable databases. The browser workflow was exercised with mocked external candidate/publication calls and the actual local evidence index. Those checks establish local functionality only.

Research data is separate from application state. The protocol in `docs/evaluation/dataset.md` requires two independent source-level identity reviews, evidence references and timestamps, per-reviewer confidence, adjudication, and an explicit uncertain outcome. Blinded local HTML packets can be prepared for a 10-query protocol pilot and later the full annotation; merge tools enforce exact query/pool coverage and emit the manifest's identity-label and relevance-judgment CSV schemas. At least 100 queries are required by the sealed-manifest validator. Identity variants are grouped by person, and an immutable freeze record binds both query membership and the test membership hash before any prediction run. Threshold development is restricted to training/development data; the held-out test split is only for the final report.

`backend/scripts/seal_evaluation_manifest.py` records hashes and verifies the frozen SQLite revision/publication count plus Chroma collection, document count, index version, and embedding model. `backend/scripts/replay_frozen_resolver.py` opens only the manifest-selected database snapshot in immutable read-only mode and emits versioned, non-overwriting predictions for explicit candidate snapshot IDs. `backend/scripts/capture_retrieval_predictions.py` queries a disposable copy of the sealed vector index and confirms that the source index hash remains unchanged. `backend/scripts/evaluate_benchmark.py` checks exact prediction coverage and the exact frozen relevance pool, computes separately denominated identity/retrieval metrics, and writes input hashes. Synthetic fixtures test these controls; they are not research data.

The 12 historical manual choices remain only a descriptive pilot. No validated identity dataset or publication relevance pool is present, so no baseline benchmark or controlled retrieval comparison has run. Retrieval currently does not affect V1 identity decisions. Future retrieval comparisons must use identical query sets and a complete blinded relevance pool; explanation quality additionally requires human claim-to-source review beyond citation-ID validity. Report coverage, abstentions, source failures, and uncertainty with quality metrics.
