## 1. Classification Taxonomy

Every architectural, methodological, and experimental claim in the research paper must adhere strictly to one of the following five evidentiary states:

- **VERIFIED:** Directly supported by reproducible benchmark data, cryptographic manifests, code implementations, and automated test executions.
- **PARTIALLY VERIFIED:** Genuine engineering implementation and initial experimental evidence exist, but the empirical claim is broader than the tested sample size or lacks independent external human adjudication.
- **UNSUPPORTED:** Conceptual claim or goal with no corresponding empirical evaluation, benchmark dataset, or reproducible test evidence.
- **CONTRADICTED:** Claim directly conflicts with empirical data, current code behavior, or physical database states.
- **PROPOSED:** Planned future work, design aspiration, or non-evaluated extension explicitly demarcated as such.

---

## 2. Explicitly Prohibited Claims (Blacklist)

The following claims **must never appear** in the revised manuscript:
1. **"Zero false merges as an absolute guarantee":** Prohibited. 0 false merges is an empirical observation on a specific 50-pair sample and a 100-query benchmark, not a mathematical theorem or universal guarantee.
2. **"Zero hallucinations / hallucination-free generation":** Prohibited. Gemini explanation safety is enforced via a syntactic citation-ID membership filter, not semantic entailment verification.
3. **"Complete author disambiguation / 100% solved entity resolution":** Prohibited. Author resolution is conservative, abstaining on 87% of queries (52 manual review, 35 unresolved) in Benchmark V3.
4. **"100% test coverage":** Prohibited. The backend suite executes 78 passing automated tests; it does not achieve 100% branch or line coverage.
5. **"Fully autonomous author resolution":** Prohibited. HAMMER is architecturally designed as a human-in-the-loop system where ambiguous cases require human selection.
6. **"Semantic retrieval improves V1 author identity decisions":** Prohibited. Dense vector retrieval in ChromaDB is isolated to publication discovery; it does not feed into or alter the deterministic Author Resolution V1 scoring or decision logic.
7. **"960 duplicate groups represent 960 evaluated pairs":** Prohibited. The 960 rows in SQLite represent application state grouping; deduplication evaluation was conducted on an adjudicated 50-pair benchmark.
8. **"Citation containment proves factual correctness":** Prohibited. Validating that a model-cited ID exists in the prompt context does not prove that the generated text accurately represents the cited publication.
9. **"Live Google Scholar / Faculty web scraping fully productionized":** Prohibited. Connectors have circuit breakers and rate limits, with Scholar disabled by default due to anti-bot defenses.

## 4. Evidentiary Boundary Rules for Manuscript Revision

1. **Numerical Honesty:** All performance metrics must cite exact denominators (e.g., 33/33 decided duplicates, 50/50 confirmed author recall, 13/100 automatic resolutions).
2. **Abstention Framing:** Emphasize that manual review referral (52%) and unresolved status (35%) are deliberate safety mechanisms against identity corruption, not system failures.
3. **Database Distinction:** Clearly distinguish between the operational application instance (396 publications) and the experimental benchmark dataset (454 publications / 2,053 source records).
4. **Scope of RQs:** Explicitly state the boundaries of the research questions:
   - *RQ1 (Semantic Retrieval):* Exploratory proof-of-concept on 20 queries, not a scaled comparison against BM25/hybrid baselines.
   - *RQ2 (Author Resolution):* Evaluates deterministic multi-signal scoring against gold OpenAlex profiles; candidate recall is separated from decision precision.
   - *RQ3 (LLM Explanations):* Evaluates structural and citation containment defense; semantic faithfulness is identified as future work.
