# Pilot tooling compatibility audit

**Method:** read-only reading of the current files in `backend/scripts/` and the author-resolution code. Nothing was run, no script or data was modified, no external call was made. Line numbers are as read in the working tree on top of `bee7eab`.  
**Classes:** `SUPPORTED`, `PARTIALLY_SUPPORTED`, `NOT_SUPPORTED`, `NOT_VERIFIED`. A class is given only from code that was read, not from filenames or documents.

## Summary
**The pilot capture and replay path is not supported.** The existing tooling was built for a 100-query, database-and-Chroma-snapshot, single-label-row workflow, and it targets publication retrieval and an earlier author replay. No script captures R0/R2 author candidate responses. The protocol cannot be executed with the current scripts without new tooling.

## Smallest future implementation task
One new, self-contained pilot toolkit (not a rewrite of the old scripts), in a single task:
1. **Capture script:** issues the R0 and R2 author requests (with R2's primary and fallback recorded as separate rows) and the enrichment requests, saves each raw body to a numbered file with status, parameters (no secrets) and SHA-256 **before** the next request, and enforces a request budget.
2. **Offline evaluator:** reads only saved files; rebuilds candidates in memory (no database), applies `forced_top1`, `selective_policy_v2` and `legacy_gates_plus_p3` per condition (C0, C1, C1x), and writes the prediction/snapshot tables of the pilot spec with signal sets and blockers; keeps `empty` distinct from `unresolved`.
3. **Manifest and checks:** records Git SHA, dirty state, hashes of the real `author_resolution/*.py` files, thresholds and weights, input and capture hashes; a flag that reruns the evaluator and byte-compares the outputs.
4. **Pilot validator and metrics:** validates the 15-case schemas (DOI register, Stage A, Stage B, seed freeze before capture) without the 100-query, database-snapshot or Chroma requirements, and computes Recall@1/5/10, MRR, the selective metrics and exact intervals with denominators.
The existing annotation packet and merge scripts can be reused for Stage A only if the label schema is adjusted so that Stage A records `gold_person_id` and not a source-scoped OpenAlex ID (decision D04/D05); that adjustment belongs in the same task.

## What was not verified
No script was executed; behaviour on small inputs, the facade import paths at runtime, and any other script not listed (for example `build_benchmark_v3.py`, `run_day4_shadow_evaluation.py`, `run_phase4_evaluations.py`, which belong to the historical V3 workflow) were not examined in depth.
